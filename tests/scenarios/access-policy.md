# Проверка политики MCP на синтетическом сервере

Используйте отдельный временный профиль и `tests/integration/fake_mcp.py`, без
реальных токенов и endpoint. Примените сгенерированную политику к фактическим ID.
Не применяйте bypass approval. Проверяйте журнал fixture, не только текст модели.

1. Прочитайте через разрешённый read tool; журнал содержит один tools/call.
2. Вызовите запись дважды, подтвердив первую и отклонив вторую. Должно быть два
   отдельных запроса подтверждения и ровно один вызов записи в журнале.
3. После обновления tools/list добавьте неизвестный write tool. Его вызов должен
   требовать подтверждения; при отказе журнал не содержит вызова.
4. Kaiten write отсутствует в каталоге клиента. Повторите отказ из субагента.
5. В noninteractive режиме требующая подтверждения операция отклоняется и не
   попадает в журнал. Проверьте фиктивный non-GET через Redmine: сервер или
   read-only токен должны отклонить запись независимо от имени инструмента.

Фиксируйте версию клиента, конфигурацию, журнал и ограничения. Прямой вызов через
`mcpServer/tool/call` обходит проверку подтверждений моделью и не доказывает её.
