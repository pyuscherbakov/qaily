# Сценарии coverage-gap-design

Использовать синтетические `tests/fixtures/openapi.json` и `tests/fixtures/swagger-coverage.json` с fake TestOps MCP и журналом вызовов. Ответы поиска задаются независимо для каждого случая; create считать по имени вызова в журнале, не по `write_count`.

| Сценарий | Проверяемый результат |
|---|---|
| POST /cohorts, createCohort: 201 покрыт, 400 не покрыт | Таблица пробелов и кейсов содержит 400, не повторяет 201; создаваемый кейс получает `api-post-cohorts` и `createCohort`. |
| Повторный запуск после создания кейса на 400 | Поиск и развёрнутый сценарий обнаруживают его; ноль дублей и ноль create. |
| Поиск TestOps вернул ошибку | «Не проверено», а не пустое покрытие; создание потенциальных дублей блокируется. |
| Один и тот же OpenAPI документ через локальный файл и URL | Одинаковые операции, параметры X-Client, схема тела и ответы 201/400; URL возвращает исходный документ, не пересказ. |
| Отказ таблицы; отказ первого или второго отдельного tools/call | Отклонённые вызовы не достигают сервера; approval таблицы не заменяет approval каждого вызова. |
| Default / явно 37 | Таблица содержит название и ID, все вызовы и ссылки используют 1 / 37 соответственно. |

Сценарии описывают ожидаемое поведение, а не факт прохождения. Положительную запись проверять только в интерактивной среде с действующей политикой и отдельными подтверждениями.
