# Сценарии review-autotest

Синтетический источник — `tests/fixtures/review.json`, `tests/fixtures/autotests/`, `tests/fixtures/mr.diff` и fake MCP с журналом `tools/call`. Работа из установленной копии с пробелами/Unicode и чужого cwd. `test_example.py` — входные данные ревью, исключённые из pytest collection; его дефекты намеренные. Проверять каждый вызов агента, вывод и журнал, а не только наличие текста инструкции.

| Режим / вход | Наблюдаемый результат |
|---|---|
| Одиночный 39979 | Один изолированный reviewer получает абсолютный `procedure_path`, `case_id=39979`, `projectId=1`, `cwd`, `формат=полный`; родитель не читает код inline. Агент читает кейс, общий шаг и `conftest.py`; четыре блока рассматриваются, совпадение fixture с предусловием учитывается, отсутствующий ОР шага отмечается только по факту. |
| URL `/project/37/test-cases/39979` | В агент и TestOps уходит 37; при конфликте с явно указанным 1 уточнение до TestOps. |
| MR с `mr.diff` и `test_example.py` | Различаются `@allure.id("39979")`, `allure.dynamic.id(str(case_id))` с параметрами 39980/39982 и `test_calc_restart_without_case` в том же файле; каждый case_id получает отдельное ревью, тест без ID — режим `file+tests`, замечание блока 4, одна строка с `Кейс —`; итоговая таблица и детали только по непустым/частичным результатам. |
| Пачка задачи #123 | `redmine_request` GET `issues/123.json` с attachments/journals ровно один раз; требования переданы каждому агенту как данные, повторного Redmine нет. При недоступном отдельном кейсе — статусная строка с причиной, остальные кейсы продолжаются. |
| MR без изменённых тест-файлов | Ответ «в MR нет автотестов» и остановка до вопроса `projectId` и TestOps. |
| Ошибка GitLab/diff или TestOps поиска списка | Остановка без частичной таблицы. |
| Агент вернул усечённую строку, неверный счётчик или неполный ответ | Не включать как «Готов»; показать явную частичность/ошибку, не терять остальные результаты. |
| Блок 1 или 2 не проверен, включая недоступное вложение | `⚠ проверено частично` при нуле замечаний, `Нужна доработка` при замечаниях с явной строкой «Не проверено»; «Готов» запрещён. |

В обеих платформах журнал содержит только чтение TestOps и Redmine; ни статусы, ни поле «Назначен» не меняются. При недоступном изолированном делегировании остановить зависимый режим, не подменяя его inline ревью. Сценарии — критерии, не факт прохождения.
