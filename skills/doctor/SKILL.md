Определи фактический клиент и инструменты. Разреши абсолютный путь этого файла через символьные ссылки к установленной копии и прочитай `../../references/platforms/claude.md` или `../../references/platforms/codex.md` и `../../references/project-selection.md`. ## Проверки без записи

Проверяй отдельно и сообщай статус ok, error или not_checked и причину, не раскрывая значения секретов, заголовки, query URL или содержимое ошибок:

1. **Зависимости:** наличие `uv`, `node`, `git`; отдельно доступность browser MCP и его ресурсов. Недоступность необязательного browser не блокирует review-testcase.
2. **Ресурсы установленного плагина:** отдельно от browser проверь только чтением наличие и читаемость файлов в разрешённой установленной копии: `.codex-plugin/plugin.json` и `.mcp.json` для Codex либо `.claude-plugin/plugin.json` и `mcp-servers.json` для Claude; `skills/{test-design,coverage-gap-design,review-testcase,review-autotest,launch-triage,doctor}/SKILL.md`; `references/project-selection.md`, `references/projects.json`, `references/platforms/{codex,claude}.md`, `references/agents/{autotest-reviewer,doc-researcher,failure-analyst}.md`, `references/policies/read-tools.json`; `bin/qaily_launch.py`, `bin/qaily_config.py`, `bin/qaily_diagnostics.py`. Недоступный или отсутствующий файл отметь error или not_checked с безопасной причиной, не выводя содержимое. При ограничении sandbox не расширяй права и не обходи его.
3. **Конфигурация и секреты:** для Claude выполни `uv run -q --script "<installedPath>/bin/qaily_launch.py" check`: legacy raw-токены (`QAILY_ALLURE`/keyring) и HTTP по текущим settings, не состояние подключения MCP. Для Codex выполни `uv run -q --script "<installedPath>/bin/qaily_launch.py" check-codex --config "<путь к применённому config.toml>"`; это проверяет остальные сервисы в окружении диагностической команды (оно может отличаться от среды Codex) и отдельно распознаёт единственное top-level подключение и его режим. Передавай `--same-process-env` только если точно известно, что окружение этой команды совпадает с окружением работающего процесса Codex, включая keyring; иначе среда `not_checked`. При несовпадении URL, двух подключениях, неизвестной конфигурации или bundled TestOps — `not_checked`/error, не выдавай проверку другого URL за состояние активного MCP. Конфигурация на диске не доказывает, что она загружена процессом. Context7 необязателен. Отсутствие keyring / Secret Service — объясни возможность задать необходимые `QAILY_<NAME>` пользователем вне чата. Jam при необходимости предложи авторизовать через OAuth клиента. Не запускай `headers`: его вывод содержит авторизацию.
4. **HTTP:** 200 подтверждает только ответ HTTP. 401 может означать ошибку авторизации; 403 также может означать недостаток прав. Сетевая ошибка может означать VPN, регион или недоступность сервиса, а не неверный токен. По данным пользователя официальный TestOps endpoint доступен только из РФ.
5. **MCP:** через доступные инструменты клиента, без самописного MCP-клиента, отдельно проверь initialize, каталог и безопасное чтение без изменения данных. Если инструменты или доступ отсутствуют, укажи not_checked и причину. Проверь доступность каталога вложений только чтением; отказ sandbox сообщи без запроса расширения прав и без обхода ограничений.
6. **Политика:** отдельно проверь статическую конфигурацию и наблюдаемое применение через разрешённые средства клиента. Наличие конфигурации не доказывает enforcement. Не выполняй запись и не обходи подтверждения для проверки.

В Codex top-level `QAILY_TESTOPS_AUTHORIZATION` содержит полный заголовок `Api-Token ...`, задаётся пользователем в окружении процесса отдельно от raw `QAILY_ALLURE` и keyring; автоматической конвертации нет. Не проси и не печатай значение. Для уже применённого config проверь актуальность пути `http_headers_helper`, если он настроен, без вывода пути или содержимого файла; если TOML parser недоступен (например Python 3.10), сообщи not_checked. Изменения секретов могут требовать перезапуска клиента. Runtime policy, работа реальных сервисов и дочерних процессов не подтверждаются статической проверкой.
