# Проверка Qaily 0.5.0 на Windows

Это план ручной проверки, а не отчёт о прохождении. Записывайте версии ОС и клиента,
поверхность (CLI или desktop), результат и несекретные доказательства отдельно для
каждого запуска. Текущее покрытие — в [матрице приёмки](codex-validation.md).

1. Установите Git, Node.js 20+, uv и выбранный клиент; проверьте их версии в новом
   PowerShell. Выполните установку для [Codex](codex-install.md) или Claude из README.
   Проверьте шесть skills и семь MCP ID в установленном пакете.
2. Проверьте свежую установку, обновление и повторную установку на изолированном
   профиле с фиктивными значениями. Сохраните снимки несекретной конфигурации до и
   после; проверьте отсутствие дубликатов и сохранение посторонних настроек.
3. Отдельно проверьте холодный запуск uv/npx, путь с пробелами и Unicode и PATH
   desktop. Проверьте keyring и переменные окружения, смените фиктивный токен и
   перезапустите клиент. Не выводите значения секретов.
4. Для TestOps используйте официальный endpoint; по данным пользователя он доступен
   только из РФ. Для Codex рекомендуемая необязательная top-level настройка и полный
   заголовок окружения описаны в [инструкции](codex-install.md). Legacy helper в Codex
   не подтверждён. Сеть, авторизация и политика доступа — отдельные проверки.
5. Проверьте `/qaily:doctor`, шесть сценариев из `tests/scenarios` и разрешения
   клиента. Для Claude отдельно проверьте выполнение общей процедуры из установленного
   cache и сохранение deny/ask. Для браузера используйте только согласованный тестовый URL.
6. Проверяйте живое чтение и Jam OAuth только при доступных сервисах и авторизации.
   Запись выполняется только после выбора тестового проекта и отдельного подтверждения
   каждого вызова. Без этого отметьте live-write как not_checked; проект 1 по умолчанию
   не является разрешением создавать тестовые данные.
